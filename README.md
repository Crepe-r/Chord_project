# ChordFinder

Клиент-серверное приложение для поиска песен и аккордов. Пользователь ищет композицию в десктопном клиенте, сервер находит её в базе данных или собирает с внешних сайтов, сравнивает найденные варианты аккордов и сохраняет лучший. Есть регистрация, двухфакторная защита, избранное, плейлисты и панель администратора.

## Возможности

- Поиск песен и аккордов по названию или исполнителю. Если песни нет в базе, сервер находит её на внешних сайтах и добавляет в базу.
- Выбор наиболее подходящего варианта аккордов из нескольких источников.
- Регистрация и вход, токены JWT (access и refresh), хеширование паролей через bcrypt.
- Двухфакторная аутентификация (TOTP): настройка через QR-код в приложении-аутентификаторе.
- Избранные песни и плейлисты, счётчик просмотров.
- Роли `user` и `admin`: администратор может добавлять, редактировать и удалять песни, а также управлять пользователями.

## Стек

- Сервер: Python, FastAPI, Uvicorn, Pydantic
- База данных: PostgreSQL, SQLAlchemy, psycopg2
- Безопасность: JWT (python-jose), bcrypt, TOTP (pyotp)
- Парсеры: requests, BeautifulSoup
- Клиент: PyQt6, requests, qrcode

## Запуск

### 1. Требования

- Python 3.11 или новее
- PostgreSQL

### 2. Установка зависимостей

```
git clone https://github.com/Crepe-r/Chord_project.git
cd Chord_project
python -m venv .venv
# Windows: .venv\Scripts\activate    Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
```

### 3. База данных

Создайте пользователя и базу в PostgreSQL:

```
CREATE USER chordfinder_user WITH PASSWORD 'ваш_пароль';
CREATE DATABASE chordfinder OWNER chordfinder_user;
```

Создайте файл `server/BD_login.py` с паролем (файл не попадает в репозиторий, он указан в `.gitignore`):

```
password = 'ваш_пароль'
```

Таблицы создаются автоматически при первом запуске сервера. Адрес подключения по умолчанию: `postgresql://chordfinder_user:<пароль>@localhost:5432/chordfinder`.

### 4. Секретный ключ JWT

Задайте ключ переменной окружения, иначе будет использовано значение по умолчанию, которое подходит только для разработки:

```
# Linux/macOS
export JWT_SECRET="длинная-случайная-строка"
# Windows PowerShell
$env:JWT_SECRET="длинная-случайная-строка"
```

### 5. Сервер

```
cd server
python main.py
```

Сервер запустится на `http://127.0.0.1:8000`, интерактивная документация API (Swagger UI) доступна на `http://127.0.0.1:8000/docs`.

### 6. Клиент

В новом терминале:

```
cd client
python main.py
```

Адрес сервера задан константой `API_URL` в `client/main.py`. Данные сессии клиент хранит в `client/session.json` (в репозиторий не попадает).

### Администратор

Роль `admin` не выдаётся при регистрации. Назначьте её вручную в базе данных:

```
UPDATE users SET role = 'admin' WHERE username = 'ваш_логин';
```

## Как работает поиск

1. Сервер ищет запрос в базе данных.
2. Если ничего не найдено, запускаются два парсера (`amdm.ru` и `chorder.ru`), каждый возвращает название, исполнителя, текст и список аккордов.
3. `song_handler` считает частоту каждого аккорда в каждом варианте и сравнивает варианты между собой с учётом циклического сдвига (это позволяет считать похожими песни в разных тональностях).
4. Похожие варианты объединяются в группы, выбирается вариант из самой многочисленной группы. Этот подход эффективнее работает при трёх и более источниках.
5. Перед сохранением проверяются дубликаты (по адресу источника и по нормализованным названию и исполнителю). Новая запись сохраняется с пометкой `verified = false`.

## API

- Песни: `GET /api/songs`, `GET /api/songs/{id}`, `POST /api/search`
- Авторизация: `POST /api/auth/register`, `POST /api/auth/login`, `POST /api/auth/refresh`, `GET /api/users/me`
- 2FA: `POST /api/auth/2fa/setup`, `/verify`, `/verify-login`, `/disable`
- Избранное: `GET`, `POST /api/favorites`, `DELETE /api/favorites/{song_id}`
- Плейлисты: `GET`, `POST /api/playlists`, `DELETE /api/playlists/{id}`; песни плейлиста: `GET`, `POST`, `DELETE /api/playlists/{id}/songs/...`
- Администратор: `POST`, `PUT`, `DELETE /api/songs`, `GET /api/admin/users`, `DELETE /api/admin/users/{id}`

Полное описание запросов и ответов доступно в Swagger UI на странице `/docs` запущенного сервера.

```
└── requirements.txt
```

## Ограничения и планы

- Парсеры зависят от вёрстки сайтов-источников и могут перестать работать при её изменении.
- Автоматических тестов пока нет, проект проверялся вручную.
- Планы: покрыть API тестами (pytest), добавить Dockerfile и docker-compose для сервера и PostgreSQL, подключить третий источник аккордов, настроить проверку тестов через GitHub Actions.
